# StatusFlare 运行说明

## 调度与运行限制

应用限制位于 `shared/policy.ts`，调度实现在 `server/scheduler.ts`，数据清理实现在 `server/cleanup.ts`。

| 项目           | 默认值                                                 |
| -------------- | ------------------------------------------------------ |
| 每分钟到期目标 | 最多 20 个，最多 5 个并发                              |
| 单个检测间隔   | 最短 60 秒，新建默认 600 秒                            |
| 每日保护上限   | 48,000 次，UTC 日切换；每分钟限制下实际最多 28,800 次  |
| 监控数量       | 最多 50 个，包含暂停项                                 |
| 通知渠道       | 最多同时启用 5 个，停用项不计入；每分钟最多尝试发送 2 条 |
| D1 写入保护    | 每日记录达到 80,000 行后暂停检查与写操作，UTC 次日恢复 |
| 每次调用 SQL   | 最多 49 条业务 SQL，另留 1 条计量 SQL                  |
| 关键词检测正文 | 最多读取 64 KiB                                        |
| 检测/渠道配置  | 单个加密前配置上限 8 KiB                               |
| 状态页         | 每 30 秒刷新，公开响应边缘缓存约 30 秒                 |
| 公告           | 每条关联最多 20 个服务，最多 5 个新附件                |
| 附件           | 可选 R2，每个上限 1 MiB                                |

计划量按启用监控的 `86400 / interval` 求和，超过 48,000 次/天会拒绝保存。超过实际每分钟处理能力的配置可以在计划上限内保存，但目标会顺延；后台会显示这两个上限。默认间隔不会因更新代码自动改变。

Cron 每分钟运行一次，间隔按分钟粒度调度。重复触发同一分钟不会重复启动批次，探测前会预扣当天额度。运行中断时额度不退还，以避免重复执行突破上限。内部探测失败也保存尝试时间，避免长期占据名额。

每轮使用一个持久化租约，过期结果不提交；修改或暂停监控后，旧版本结果不生效。长超时可能使整批跨分钟，下一轮会等待，而非无限叠加并发。

## 数据存储

后台“页面设置”支持 HTTPS 背景图片 URL 和 0–1 的背景压暗程度（默认 0.6）。保存后公开首页及事件历史页对所有访客生效，已登录管理后台也使用相同背景与压暗设置；清空 URL 恢复纯色，无需数据库迁移。图片由访客直接加载，地址会公开；图床需允许状态页来源的 CORS（`Access-Control-Allow-Origin`）和 Referer 校验。背景图片使用 `crossorigin="anonymous"` 和 `referrerpolicy="strict-origin-when-cross-origin"`，跨域不携带图床登录 Cookie。加载失败回退纯色；压暗仅影响背景。

后台“监控 → 编辑”可设置“排序（越小越靠前）”，用于调整同一服务下的监控展示顺序。数值相同时按创建时间、ID 排序；已有监控默认值为 0，保留原有顺序。此功能需要应用 `0008_monitor_position.sql` 迁移。

后台“监控”列表将启用／暂停设置与健康状态分开显示。健康状态根据最近一次检测展示正常、异常、待检测、已暂停或数据过期；新建或配置更新后等待新结果，超过检测间隔两倍加 30 秒的结果标为过期。正常检测显示毫秒响应时间，失败检测标为“检测耗时”；暂停或过期结果的耗时注明“上次检测”，当前配置没有有效耗时显示“—”，0 毫秒仍正常展示。点击“刷新”获取最新记录，此展示无需数据库迁移。

- 在线配置、服务分组、公告、审计记录存 D1。
- “服务 → 编辑”可设置整个服务的统一公开访问链接，显示为“访问服务”；“监控 → 编辑”也可单独设置公开访问链接，在该监控标题右侧显示可点击的网址（新标签页打开）。两者可同时使用，监控链接留空时不显示、不继承服务链接，也不会公开检测网址。链接支持公开 HTTP/HTTPS 地址。监控链接需要应用 `0009_monitor_link.sql` 迁移，已有监控默认留空。
- 敏感检测/通知配置由 ENCRYPTION_KEY 加密。
- `free_runtime` 合并保存所有最新状态和批次调度信息。
- `free_history` 每小时一行，保存各监控的 `[小时内秒数,延迟,是否正常]` 数组。
- `free_daily` 每天一行，合并正常/异常秒数和延迟统计。
- 故障开始和恢复写入 `monitor_outages`，通知存 `notification_outbox`，与快照事务一起提交。
- 原始样本目标保留 7 天，详情图展示最近 12 小时；日统计目标保留约一年，页面展示最近 90 天。清理分批执行，积压时会保留更久。
- 公开状态页在当前页面内缓存已加载的监控详情。同一监控、同一检测时间下重复展开直接复用，也会共享尚未完成的请求；检测时间变化后才重新读取，收起期间不主动请求详情。失败请求下次展开可重试，不再公开的监控会移除缓存。缓存仅保存在页面内存中，刷新整个页面或离开页面后清空。
- 开启 R2 后，过期原始数据先归档再删除；页面不会自动读取归档对象，归档用于另行下载和分析。

`migrations/` 是数据库的增量迁移历史，已应用的文件不得修改或删除。`free_*` 是已有存储表的兼容名称；这些表以及旧版本数据表继续保留，避免升级影响已有状态和历史数据。

需要导入历史时，`scripts/import-legacy.mjs` 接受已导出的 JSON 文件，目标地址通过 `STATUSFLARE_URL` 指定。脚本使用 `prepare-history.mjs` 在本地计算统计，再按每批最多 20 条记录提交；中断后可使用同一文件继续。

## 通知正文模板

“公告与维护 → 新增 / 更新”提供“通知渠道”多选框，只列出启用渠道。每次打开编辑框都默认不选，选择仅用于本次公开发布或更新，不随公告保存；留空仍可公开发布，但不发送通知。保存草稿不发送通知。通知只进入所选且仍启用的渠道队列，后续进展需要重新选择；检测异常与恢复通知仍使用全部启用渠道。此功能无需数据库迁移。

后台“页面设置 → 通知正文模板”可分别编辑检测异常、检测恢复和公告发布 / 更新三个模板，支持示例预览及恢复默认。检测异常支持 `{{monitorName}}`、`{{reason}}`、`{{time}}`；检测恢复支持 `{{monitorName}}`、`{{time}}`；公告支持 `{{title}}`、`{{kind}}`（公告类型：故障事件 / 计划维护）、`{{services}}`（受影响服务名称，按关联顺序去重后以顿号连接）、`{{status}}`、`{{severity}}`（影响程度：轻微影响 / 主要故障 / 严重故障）、`{{body}}`、`{{time}}`、`{{startTime}}`（预计开始时间）、`{{endTime}}`（预计结束时间，未设置时显示“待定”）。“通知时区”统一控制这些模板的时间显示，支持 `Asia/Shanghai`、`America/New_York` 等有效时区并自动处理夏令时。默认 UTC 保留 ISO 格式；其他时区显示例如 `2026-09-22 16:00:00 UTC+08:00`。此设置仅影响通知模板，页面显示和时间输入仍按浏览器本地时区处理，公告状态为中文名称（例如 investigating 显示为“调查中”、resolved 显示为“已解决”），正文为本次提交的进展（未填写时为空）。模板最长 4,000 字符，不能为空或包含未知变量；变量值只替换一次，不执行表达式。

模板统一生成各 Webhook 渠道的 `$MSG` 正文，渠道配置仍负责请求体结构。保存后用于新入队通知，已入队消息和重试保持原正文；渠道编辑窗口的连接测试仍使用固定测试文案。未配置时沿用原文案。模板单独保存在现有 `settings` 表中，无需迁移，不通过公开状态 API 返回。

“通知正文模板 → 真实模板测试”可选择已保存渠道以及检测异常、检测恢复、故障公告或维护公告，使用当前编辑（可以尚未保存）的模板和时区真实发送一次。测试使用示例数据并在消息开头添加测试标识；时间取发送时刻，维护示例预计结束时间为一小时后，故障示例为“待定”。停用渠道也可测试。测试不保存模板、不创建公告、不进入通知队列或自动重试，界面显示发送结果和耗时，审计记录为 `channel.template-test`。HTTP 成功仍需在接收端确认业务结果。通知渠道编辑窗口原有的固定文案测试保持可用。

## 备份现有加密密钥

密钥备份下载默认关闭。需要找回当前 `ENCRYPTION_KEY` 时：

1. 发布包含密钥备份功能的版本，保留原来的 `ENCRYPTION_KEY`。
2. 在 Cloudflare 的 Worker → Settings → Variables and Secrets 中临时添加 **Secret** `ENABLE_KEY_EXPORT`，值为 `true`，并应用变更。不要修改 `ENCRYPTION_KEY`。
3. 通过 Access 管理员身份进入本站后台，在“页面设置 → 密钥备份”点击“下载密钥备份”，浏览器会下载 `statusflare-encryption-key.env`。确认文件已保存，将它与对应的 D1 备份妥善保管；不要提交到仓库。
4. 回到 Cloudflare，删除 `ENABLE_KEY_EXPORT` 并应用变更，即关闭下载入口。刷新后台后入口消失。

接口只接受本站发起的 POST 下载请求，不接受管理 API Token；本地开发身份仅在原有本地认证条件下可用。响应禁止缓存，操作记录只保存下载动作和管理员身份，不记录密钥。此功能不更换密钥，也不改写监控或通知配置。下载失败时可在关闭入口前重试。

## 限制与观察

后台“运行记录”右上角提供“一键清理”。确认后，会在同一事务中永久删除全部操作记录／审计日志和通知投递记录，包括列表未展示的历史记录，以及待发送、发送中和等待重试的通知。待发送和等待重试的通知不再投递，已经开始发送的通知仍可能送达。此操作不可撤销，不额外保留本次清理的审计记录；监控历史、公告和通知渠道配置不受影响，新产生的运行记录会继续正常保存。接口要求管理员认证和明确确认，并受应用写入预算限制。通知中已发送、取消或失败的记录平时仍按创建超过 30 天自动分批清理，操作记录没有自动保留期；两类记录在后台各展示最近 100 条。

通知渠道编辑窗口提供“发送测试通知”：使用已保存配置真实发送一条带测试标识的消息，停用渠道也可测试。修改配置须先保存；测试不自动重试、不生成故障事件，管理员窗口显示 HTTP 状态、耗时、失败响应正文（最多 16 KiB）或具体异常信息，运行记录保留 `channel.test` 审计。详细错误可能包含接收端返回的凭据或请求信息，仅通过管理员测试接口返回；自动通知的持久化错误仍使用通用提示。HTTP 2xx 只代表接收端接受请求，仍需确认目标应用收到消息。

应用写入计量使用 D1 返回的 metadata，预留余额，但并发、失败事务、进程中断和账号其他应用会使计量与平台额度存在差异。它不是账号计费硬上限。频繁故障切换与大量待发通知也会增加写入。

部署后通过 Worker Metrics 和 D1 Metrics 观察请求、CPU、错误、数据库读写及存储用量。应用预算不能代替平台计量，本地测试也不能证明线上每次调用都满足资源限制。参考 [Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)、[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)、[D1 计量](https://developers.cloudflare.com/d1/platform/pricing/)。

维护会静默自动通知，但仍记录检测和可用率；自动恢复不会自动关闭人工发布的事件。未知检测缺口不会全部视为正常。通知投递采用重试，外部已接收但本地确认失败时可能重复。
